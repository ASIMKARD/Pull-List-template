# Pull List template v3

The base every Pull List comic reading-order tracker is built on: one data file,
one build step, an offline web app, a generated workbook, and two test suites
(jsdom and real Chromium) that CI runs on every push.

- **Rules for every session:** `CLAUDE.md`. **Where the work stands:** `PROGRESS.md`.
- **Conventions** (versions, skins, the signature skin, the workbook, the gate): `BUILD-NOTES.md`.
- **Moving a live tracker onto v3** without losing anyone's progress: `MIGRATING.md`.
- **The parity checklist** v3 must clear: `FEATURE-INVENTORY.md`.
- Claude sessions load the `comic-tracker-build` Skill from `.claude/skills/comic-tracker-build/SKILL.md`.

## Start a tracker, step by step

1. **Get a fresh repo.** John creates it. Copy this template in with fresh
   history; never build a new tracker inside the template or inside a live repo.
2. **Install the test tools.** `npm ci` (jsdom, ajv, playwright-core). Cloud
   sessions do this at start-up (`.claude/settings.json`).
3. **Write `dataset.json`** — the master; everything else is generated from it.
   The schema is `schema/dataset.schema.json`; `test/fixtures/basic/dataset.json`
   is a complete invented franchise that uses every feature.
   - `franchise`: `key` (unique across every tracker you host: it namespaces
     saved progress, the QR prefix and the cache name), `wordmark`, `title`,
     `strapline`, `span`, `theme`, and optionally `background`, `searchUrl`,
     `icons`, `skins` / `skin`, `signature`, `storage`, `versionStart`.
   - `eras` with ranks from 5000, spaced 10; `periods` (optional bands);
     `strands`, `types`, `tiers`, `media`; `arcs`.
   - Rows inline (`rows`) or one file per era (`sources`, schema
     `schema/era-file.schema.json`; the basic fixture keeps them in
     `test/fixtures/basic/data/eras/`). Every row has an `issueId` and a
     sourced date (`date: {cover, onsale?, source}`); keys are derived, never written.
   - Shared events live in `events/` (schema `schema/event.schema.json`); each
     one the tracker joins is listed with its era in `dataset.json`.
   - `deliverables`: the workbook is on unless you set `{"workbook": false}`
     (web-app-only trackers).
4. **Replace the icons.** Put the franchise's own PNGs in `icons/` or point
   `franchise.icons` at them (192, 512 and maskable 512). The build warns while
   the template's placeholders are still in use.
5. **Build.**
   ```
   python3 tools/build.py            # data.js, sw.js, manifest.json and workbook.xlsx
   python3 tools/build.py --check    # are the committed generated files fresh?
   ```
   The build fails loudly, listing every problem. Never hand-edit what it writes.
6. **Run the gate.** `python3 tools/verify_gate.py` runs Research-Repo's
   verify.py (pinned as `tools/verify.py`, recorded in `tools/verify.lock`)
   on the stitched data and checks the order the app shows. A failure means
   do not ship.
7. **Run both suites and report the counts.**
   ```
   node test/run.js          # jsdom harness: build, data, the real app
   npm run test:layout       # real Chromium: overflow, fit, contrast, the stack, motion, fonts, offline, paint
   ```
   Any failure, any crash, or zero assertions fails a run.
8. **Deploy** (GitHub Pages). The first deploy uploads everything, `fonts/`
   and `icons/` included. Wait about 100 s, then check the version in the
   header and verify changed files by hash, not by HTTP 200. Open the
   installed app once online; Settings → Offline should read "Ready offline".

## What's where

| Path | What it is |
|---|---|
| `dataset.json`, its per-era files, `events/` | the master data (edit these) |
| `data.js`, `sw.js`, `manifest.json`, `workbook.xlsx` | generated by `tools/build.py` — never hand-edit (it also stamps `index.html`'s links with the build) |
| `index.html`, `app.js`, `styles.css`, `qrcode.js`, `fonts/`, `icons/` | the app shell |
| `tools/build.py` | stitch, derive keys, validate, emit (stdlib only) |
| `tools/build_workbook.py` | the workbook writer (stdlib only) |
| `tools/verify_gate.py`, `tools/verify.py`, `tools/verify.lock` | the verify gate and its pinned copy of verify.py |
| `tools/templates/sw.js` | the service-worker template the build fills in |
| `schema/` | JSON Schema for the data files |
| `test/run.js`, `test/suites/`, `test/lib/` | the jsdom harness |
| `test/layout/`, `test/layout/ref/` | the Chromium suites; the Pull reference |
| `test/fixtures/` | basic, no-periods, mixed, minimal; broken (each fails the build), gate (each fails the gate) |
| `.github/workflows/harness.yml` | CI: freshness, fixtures, the gate, both suites |
